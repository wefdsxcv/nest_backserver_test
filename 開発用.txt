DI / DIP と Mock の関係

本番環境では UserService に RealDatabaseRepository を注入します。

テスト環境では、実際のDBに接続したくないため、インターフェースは同じで中身が空っぽの MockDatabaseRepository を注入します。これがDIコンテナを使う最大のメリットの一つです。

単体テスト (Unit Test)

NestJSでは標準で Jest というテストフレームワークが組み込まれています。関数やクラス単体が正しく動くかを検証します。

CI (継続的インテグレーション)

コードをGitHubなどにプッシュした際に、自動で単体テストを実行する仕組みです。今回は最もメジャーな GitHub Actions を使うのがおすすめです。

AWS (Amazon Web Services)

最初は「触ったことがない」状態でも大丈夫です。今回のゴールとしては、CIでテストが通ったら自動的にAWSのサーバー（例えば AWS App Runner や ECS、S3など）にデプロイされる仕組み（CD）を目指すと、一気に実務レベルの知識になります。
