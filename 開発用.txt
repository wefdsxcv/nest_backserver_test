～きずいた点やなどコードの詳細はコメントに書く～
NestJS では Middleware → Guard → Interceptor → Pipe → Controller → Service (repository)→ Interceptor（レスポンス）  の流れ。
インターセプタ―はリクエストとレスポンスを両方触れる。
他の言語やフレームワークでもmiddlware　でログ等共通処理を実装する。理由はcontoroler にログ出力責任（機能）を設けると　職務が汚れるため　行わない。

実務では上記のログを専用のサーバー（DB）などに保持する。また、ログのレベル（level（INFO / ERROR））に応じてslack 等に通知を発火する（webhook）等を行う。

timestamp（時刻）
level（INFO / ERROR）
type（REQUEST / RESPONSE）
method（POST）
url（/message）
body（リクエスト内容）
statusCode（レスポンス）
responseTimeMs（処理時間）   各ログ一覧。

prisma/schema.prismaファイル下部に以下の内容を記載。（TS　userId。Prisma schema	userId @map("user_id")SQL（DB）	user_idでもおけ）
// ★ここから追記
model Message {
  id        Int      @id @default(autoincrement()) // 主キー（自動連番）
  text      String   @db.VarChar(255)              // メッセージ本文（最大255文字）
  userId    Int      @map("user_id")               // 誰が送ったか（ユーザーID）
  createdAt DateTime @default(now()) @map("created_at") // いつ送ったか（作成日時）

  @@map("messages") // 実際のデータベース内でのテーブル名を「messages」にする
}
